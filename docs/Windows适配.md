# Windows 原生适配

Windows 版本使用 C# / WPF / Win32，保留 macOS Swift 工程。入口 `Windows/Program.cs`；不是网页、WebView 或 Electron。默认构建为 Windows 10/11 x64 的自包含单文件 EXE。开发使用 .NET SDK 8+；运行产物不需另外安装运行时。

```powershell
./build.ps1 -Run
./build.ps1 -Package
./build.ps1 -DeliveryTest
```

## 外观和交互

当前交互：单击宠物不打开输入框，双击仅启动 / 激活绑定客户端；未绑定时打开绑定窗口。两次点击须落在同一宠物，拖动、装饰和跨角色点击不触发打开。键盘聚焦宠物后按空格或回车打开客户端。右键罐子 → 角色 →“写消息…”或 Alt+Space 仍可进入独立草稿输入框。

悬停使用原生 WPF 额度浮层，异步读取账号用量 / 剩余百分比、周期、重置时间，每 45 秒刷新，鼠标移出即关闭。明确标注本机登录来源，未知不记为 0，失败缓存标注“上次读取”，已过期周期不显示旧百分比。ChatGPT 默认是本机 Codex CLI 订阅额度，不代表其他 ChatGPT 或 API 账户；Claude 使用本机 Claude Code 只读 OAuth 兼容端点（无公开稳定 API 保证），过期不自动刷新。Grok / Muse 未接入账号接口，显示不可获取。绑定窗口可选“自动 / 本机 Codex / 本机 Claude Code / 暂不接入”，用户须确认与目标客户端账号一致。凭据不写入配置或报告，额度读取不发模型请求；更多来源与限制见 README 的账号额度说明。

260 × 260 的透明、无边框、置顶桌面窗口。玻璃的后景、内壁裁剪、原始堆叠画面、眼部补片、前景反光分层绘制。复用 `Resources/pile-scene.png`、`pile-expressions.png` 与原始角色头像。

`JarGeometry.SceneRect` 是 Swift `JarGeometry.sceneRect` 转成左上原点后的同一矩形：`(25,8,210,210)`。角色轮廓与眼部矩形保存在 `Windows/SceneLayout.json`；构建时逐项校验与 `PackedScene.swift` 一致。玻璃和内壁裁剪共用变换 `(0.90, 0.967)`，坐标换算后的平移为 `(13, 0.066)`。底部后侧弧线不盖在宠物前景。

四角色可点击、键盘聚焦并暴露原生无障碍按钮；装饰物没有消息路由。待机时四只宠物以不同相位和周期活动：ChatGPT 偶尔缓缓睁眼再休息，Grok / Muse / Claude 自然眨眼，间或双眨。hover 只变化眼部，ChatGPT 睁眼回应，其余角色轻眨后眨单眼；聊天进入时其余角色双眨，此后各角色按交替间隔眨眼，ChatGPT 保持睁眼交流。聊天活动独立于悬停，切换角色或关闭对话框后原角色平滑回到待机。左右眼独立控制，使用两端速度为零的缓动；状态切换从当前表情开始，避免突然跳变。Windows 关闭客户区动画时使用静态眼部表情。整体宠物、罐体和玻璃始终固定。

Claude 使用 `Resources/pet-claude.png` 的透明毛绒小螃蟹素材，独立放在右下方。位置为统一场景中的 `(0.55,0.74,0.40,0.24)`，沿用同一 `SceneRect`；静态底图中原有三角色的尺寸和位置不变。源图按可见轮廓裁掉透明留白，渲染、头像和眼部读取使用相同裁剪。鼠标命中进一步检查实际 Alpha，透明的钳子间隙不会路由到 Claude。原有枚举值保持不变，新角色追加在末尾，旧绑定配置兼容。客户端由安装记录和产品身份自动识别，找不到或存在歧义时使用手动绑定。

macOS 同步了角色、路由、场景位置和眼部素材。`Resources/claude-eyes.json` 与六张 `claude-eye-*.png` 是两端通用的局部材质 / 眼形资源，可运行 `PetJar.exe --export-claude-eyes <Resources目录>` 从本项目素材重新生成。Windows 构建校验源图 SHA-256、共享坐标和 Swift 布局，防止旧眼部资源混入；macOS 构建直接使用项目内文件，不依赖 Windows 工具或原对话目录。macOS 的 Claude 客户端标识采用 [Claude 官方企业配置文档](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop) 中的 `com.anthropic.claudefordesktop`；本机未构建或运行 macOS。

绘制采用保留的背景、八个眼部、前景玻璃和提示文字图层。眼部图仍从同一 `JarGeometry.SceneRect` 裁出，保留角色轮廓、内壁裁剪和边缘羽化。`EyeArtwork` 在启动时分离源素材的眼形、高光和轮廓，缓存局部材质底片；底片在原眼形区域使用周围材质的二维插值，完整遮住静态堆叠中的眼睛。每帧只压缩或展开独立眼形，局部材质和身体保持固定；睁眼与闭眼素材在眼形收至零高度时切换，始终只显示一种眼形，不使用两张眼睛的半透明交叉混合。使用 `CompositionTarget.Rendering` 跟随 WPF 合成节奏，以单调时间计算动画，过滤同一合成帧的重复回调，不再用固定 16 毫秒的 DispatcherTimer 重建整罐画面。窗口隐藏、关闭、冻结表情或系统禁用动画时解除帧回调；无表情变化时不修改图层。

拖动罐子移动，释放后限制在当前工作区并保存位置。对话框按实际点击点的高度靠罐子侧面定位，拖动罐子时保留该局部锚点；靠左边缘时翻到右侧，屏幕顶部为半露头像留出空间。右上角 × 和 Esc 收起、Alt+Space 呼出 / 收起上次角色、Ctrl+Enter 执行当前投递模式；热键冲突时仍可通过宠物或系统托盘操作。右键菜单与系统托盘提供找回位置、对话和退出。位置、角色的 `.exe` 绑定和可选窗口标题筛选存于 `%LOCALAPPDATA%/PetJar/settings.json`。草稿与投递模式按角色隔离，只在当前运行期保留，投递期间不能切换目标或改写源草稿。

## Windows 投递边界

`ClientDiscovery` 在启动时异步检查 HKCU / HKLM 的 32 / 64 位卸载记录、常见应用目录和已注册 Store 应用包；核对产品名、发布者和程序名，不能只凭宠物名称绑定其他软件。Store 清单只选择主应用 ID，不选择命令行工具或 SSH 辅助程序。固定的只读 PowerShell 库存查询有 15 秒超时，不加载用户配置、不提权；查询失败仍保留传统安装识别与手动绑定。有效手动绑定不被覆盖，自动绑定保存路径快照和 AUMID，包更新后刷新路径；手动保存时退出自动管理。自动绑定不推断会话标题，不改变已配置的投递筛选或额度来源。多个不同安装候选无法唯一确认时保留手动选择。冷启动 Store 应用使用 Windows [IApplicationActivationManager](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication)；已运行时核对程序路径并恢复 / 激活窗口，只有前台窗口一致才报告已打开。

macOS 的 bundle ID 不能用于 Windows。用户右键每个角色头像或对话框玻璃空白处，选择“绑定 Windows 客户端…”来绑定本地 `.exe`，或从已打开窗口选取该进程与标题。出现多个匹配窗口时自动填入停止，需设置标题筛选；标题筛选不能证明智能体或会话身份。用户应先在客户端选择目标会话。

默认“复制并打开”。UI Automation 通用适配执行这些检查：

1. 程序路径与窗口标题匹配，并且目标窗口唯一、处于前台。
2. 输入框具有消息语义、可读写、可见、非密码字段，且不是搜索 / 筛选 / 地址栏 / 重命名控件。
3. 目标草稿为空。设置焦点后再次读取草稿，确认焦点、窗口与剪贴板未变化。
4. 通过 Ctrl+V 粘贴，回读文本一致才报告已填入。
5. 只有邻近控件范围内唯一、启用的发送按钮才调用 InvokePattern。不盲按回车、不自动重试。

任何不确定情况都会停止。源草稿不清空；已尝试粘贴却未确认时提示检查客户端，避免重复投递。控件不支持 ValuePattern、权限不匹配、窗口变化等情形需手动粘贴。不会自行提权或改变系统隐私权限。

输入区域为 352 × 176，原生磨砂仅覆盖输入区，不再绘制外层面板。64 × 64 的宠物头像使用独立透明附属窗口，视觉中心对齐输入框上沿，内外各占一半；头像周围逐像素透明，输入区右下角保留发送按钮，右上角提供 × 关闭按钮。头像从原始素材的可见轮廓裁出，静态罐内堆叠与眼部几何不变。头像随输入框移动、角色切换和显隐，输入框贴近屏幕顶部时为外露半个头像留出空间。Windows 11 22H2 及以上优先使用原生背景模糊，叠加约 25% 至 38% 的浅色高光，让后方颜色明显透出。通过动态查找可选 SetWindowCompositionAttribute 的 BlurBehind 入口启用；该兼容接口缺少稳定的公开 AccentPolicy 契约，失败时回退到公开 DWM Desktop Acrylic，旧系统、高对比度或 DWM 失败时回退到浅色表面。绑定、投递模式和最近结果移入右键菜单。发送按钮常态显示“发送”，实际操作方式可悬停查看，沿用各角色原有投递模式。

复制、打开、填入、点击发送在投递后的短暂反馈与右键“最近投递结果”中分别报告。调用发送按钮不等于服务端接收；没有服务端确认接口、回复读取或可靠会话绑定。新 ChatGPT 草稿模式将 `codex://new?prompt=...` 参数交给绑定程序，只能报告已请求打开，不能宣称已预填。

开发诊断入口：`--self-test --test-report <path>`、`--render-expression <chatgpt|grok|muse|claude|none> <png>`、`--render-blink-strip <png>`（四个角色的七个眨眼阶段）、`--preview-lid <0..1>`（实际原生窗口冻结在指定闭合程度）、`--show-composer`、`--qa-taskbar`、`--preview-hover <client> --freeze-expression`、`--startup-log <path>`、`--animation-report <json-path>`（启动预热 1 秒后采样约 12 秒，写入合成回调间隔和各角色表情变化数）。离屏 PNG 仅作绘制验证，不能替代实际桌面窗口检查。`--delivery-test-ui --test-report <path>` 需要点击测试按钮后运行，测试消息只进入临时本地窗口。
